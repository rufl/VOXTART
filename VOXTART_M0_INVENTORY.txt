VOXTART release validation
--------------------------
- Windows release gate: ``python tests/python/voxtart_e2e.py``. It enforces the 97 core, 29 native Blender, and 7 headless editor test baseline, isolates persistence preferences, bootstraps ``scripts/addons_core`` before reopening a saved blend, validates package-relative paths, runs the packaged launcher, and exercises the visible GUI.
- Direct Linux suite entrypoints enforce the same 97/29/7 collected-test contract, so accidental test loss fails before coverage or artifact upload.
- CI downloads verify pinned official Blender 5.2.2 SHA-256 digests before extraction, and the workflow token is limited to read-only repository contents.
- All reusable GitHub Actions are pinned to immutable commit revisions, and checkout steps disable credential persistence after fetching source.
- Package assembly: ``python tools/assemble_voxtart_package.py --output <directory> --runtime-source <Blender runtime>`` creates an isolated release-copy tree and rejects runtimes missing ``blender.exe``, ``blender-core.exe``, or the bundled Python executable before copying. The E2E smoke path adds ``--link-runtime`` to avoid copying the 1.2 GiB runtime; its manifest records ``smoke-linked`` versus ``release-copy`` explicitly. Local release-copy smoke copied 6,528 runtime files with ``runtime_isolated=true`` and the packaged launcher probe passed on Blender 5.2.2.
- Current local evidence: core coverage 6917/6917 (100.000%), Blender-facing coverage 6318/14136 (44.69%), and headless performance at 32768 voxels with 514.74 ms rebuild and 63.28 ms selection in the latest artifact probe.
- Core boundary validation rejects non-finite colors/scales, lossy fractional integer inputs, malformed schema versions, malformed MCP numeric arguments, and invalid Minecraft world coordinates; deterministic and native regression suites cover these rejection paths.
- SPRITEFORM migration: ``scripts/addons_core/voxtart/provenance.py`` records canonical source identities and OUTSIDE/UNKNOWN/FREE/OCCUPIED/CONFLICT evidence; ``metrics.py`` adds IoU/depth/surface review metrics; ``reconstruct.py`` carries evidence and explicit acceptance decisions; ``pick.py`` uses finite corner-safe segment DDA; asset digests bind accepted content.
- CI evidence checks require the expected coverage, performance, baseline, GUI marker, GUI screenshot, and Windows E2E log files before upload; ``tools/validate_voxtart_evidence.py`` enforces the shared schemas, screenshot dimensions/pixel payload, and success markers, rejecting malformed or unsuccessful payloads.
- Remaining release risk: this workstation cannot execute the hosted GitHub Actions Windows/Ubuntu jobs; the workflow is checked in and the full Windows gate passes locally, but hosted-run status remains an external prerequisite before publishing.
